## Overview

Anserini provides comprehensive regression tests for the MS MARCO datasets, including:

- **MS MARCO V1**: Passage and document rankings
- **MS MARCO V2**: Passage and document rankings
- **MS MARCO V2.1**: Latest version with updated documents
- **TREC Deep Learning Tracks**: DL19, DL20, DL21, DL22, DL23
- **RAG24**: Retrieval-Augmented Generation track

## MS MARCO V1

### V1 Passage Collection

The MS MARCO V1 passage collection contains approximately 8.8 million passages. Anserini supports multiple indexing and retrieval approaches:

#### Standard BM25 Indexing

```bash
python src/main/python/run_regression.py \
  --index --verify --search \
  --regression msmarco-v1-passage
```

#### Document Expansion Variants

MS MARCO V1 supports several document expansion techniques:

- **doc2query**: Query prediction for document expansion
- **docTTTTTquery**: Enhanced query prediction with more queries per document

```bash
# docTTTTTquery regression
python src/main/python/run_regression.py \
  --index --verify --search \
  --regression msmarco-v1-passage.docTTTTTquery
```

#### Learned Sparse Representations

Multiple learned sparse indexing approaches are available:

- **UNICOIL**: Universal contextualized inverted list
- **DeepImpact**: Impact-based learned sparse retrieval
- **SPLADE**: Sparse Lexical and Expansion model
  - SPLADE++ (ED): Ensemble distillation variant
  - SPLADE++ (SD): Self-distillation variant  
  - SPLADE v3: Latest version

```bash
# SPLADE++ ED with cached representations
python src/main/python/run_regression.py \
  --index --verify --search \
  --regression msmarco-v1-passage.splade-pp-ed.cached

# SPLADE++ ED with ONNX inference
python src/main/python/run_regression.py \
  --index --verify --search \
  --regression msmarco-v1-passage.splade-pp-ed.onnx
```

#### Dense Vector Representations

Dense retrieval with multiple encoders:

- **DPR-distil**: Distilled dense passage retrieval
- **BGE-base-en-v1.5**: BAAI general embedding model
- **OpenAI Ada-2**: OpenAI embedding model
- **Cohere Embed v3.0**: Cohere embedding model

Each supports multiple index types:
- **Flat**: Exact search (slower, more accurate)
- **HNSW**: Approximate nearest neighbor (faster, slight quality tradeoff)
- **INT8**: Quantized for smaller index size

```bash
# BGE with flat index and cached queries
python src/main/python/run_regression.py \
  --index --verify --search \
  --regression msmarco-v1-passage.bge-base-en-v1.5.parquet.flat.cached

# BGE with HNSW index and ONNX inference  
python src/main/python/run_regression.py \
  --index --verify --search \
  --regression msmarco-v1-passage.bge-base-en-v1.5.parquet.hnsw.onnx
```

## Index Types Comparison

### Inverted Indexes (Sparse)
- Fast retrieval
- Smaller index size
- Lexical matching
- Good for keyword queries

### Dense Indexes (Flat)
- Exact nearest neighbor search
- Better semantic matching  
- Larger index size
- Slower retrieval

### Dense Indexes (HNSW)
- Approximate nearest neighbor
- Fast retrieval
- Slight quality tradeoff
- Good balance of speed and accuracy

### Quantized Indexes (INT8)
- Significantly smaller index size
- Minimal quality degradation
- Faster retrieval than full precision
- Recommended for production deployments
