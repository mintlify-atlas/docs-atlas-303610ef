title: Dense Retrieval
description: Dense vector search with HNSW and flat indexes in Anserini
---

Dense retrieval represents queries and documents as continuous vector embeddings, enabling semantic matching beyond exact term overlap. Anserini supports both approximate (HNSW) and exact (flat) vector search.

## Quick Start

Search MS MARCO passages with BGE-base-en-v1.5 embeddings:

```bash
java -cp anserini-1.6.0-fatjar.jar io.anserini.search.SearchHnswDenseVectors \
  -index msmarco-v1-passage.bge-base-en-v1.5.hnsw \
  -topics msmarco-v1-passage.dev \
  -encoder BgeBaseEn15 \
  -output run.msmarco.bge.txt \
  -efSearch 1000
```

**Expected Result: MRR@10 = 0.3575**

## HNSW Vector Search

Hierarchical Navigable Small World (HNSW) graphs enable fast approximate nearest neighbor search for dense vectors.

### HNSW Parameters

Key parameters defined in `SearchHnswDenseVectors.java:50-74`:

| Parameter | Description | Default |
|-----------|-------------|--------|
| `-index` | HNSW index path | Required |
| `-topics` | Topics file | Required |
| `-output` | Output run file | Required |
| `-encoder` | Encoder model class | Required |
| `-efSearch` | HNSW search beam width | - |
| `-hits` | Number of results | 1000 |
| `-threads` | Parallel threads | 1 |
| `-topicReader` | Topic format | JsonIntVector |
| `-topicField` | Field to use | vector |

<Note>
The `-efSearch` parameter controls the accuracy-speed tradeoff. Higher values improve recall at the cost of slower search. Typical values range from 100-1000.
</Note>

## Flat Vector Search

Flat indexes perform exact nearest neighbor search via brute-force comparison. While slower than HNSW, they guarantee perfect recall.

### SearchFlatDenseVectors

Use `SearchFlatDenseVectors.java:49` for exact search:

```bash
java -cp anserini-1.6.0-fatjar.jar io.anserini.search.SearchFlatDenseVectors \
  -index msmarco-v1-passage.bge-base-en-v1.5.flat \
  -topics msmarco-v1-passage.dev \
  -encoder BgeBaseEn15 \
  -output run.bge-flat.txt \
  -threads 16
```

**MRR@10 = 0.3575** (identical to HNSW with high efSearch)

### When to Use Flat vs HNSW

| Use Case | Recommended Index |
|----------|------------------|
| Small collections (under 100K docs) | Flat (fast enough) |
| Need 100% recall | Flat (exact search) |
| Large collections (over 1M docs) | HNSW (much faster) |
| Production retrieval | HNSW (good recall/speed tradeoff) |
| Research/baselines | Both (validate HNSW against flat) |

## Query Encoding

Anserini supports on-the-fly query encoding with various embedding models:

### Pre-encoded vs On-the-fly

<CodeGroup>
```bash Pre-encoded queries
java -cp anserini-1.6.0-fatjar.jar io.anserini.search.SearchHnswDenseVectors \
  -index msmarco-v1-passage.bge-base-en-v1.5.hnsw \
  -topics msmarco-v1-passage.dev \
  -topicReader JsonIntVector \
  -topicField vector \
  -output run.txt
```

```bash On-the-fly encoding
java -cp anserini-1.6.0-fatjar.jar io.anserini.search.SearchHnswDenseVectors \
  -index msmarco-v1-passage.bge-base-en-v1.5.hnsw \
  -topics msmarco-v1-passage.dev \
  -encoder BgeBaseEn15 \
  -output run.txt
```
</CodeGroup>

<Note>
Pre-encoded queries (as JSON vectors) are faster for batch evaluation. On-the-fly encoding is better for interactive applications and when query vectors aren't pre-computed.
</Note>

## Implementation Details

From source code analysis:

### HNSW Search Flow

1. **Initialize** (`SearchHnswDenseVectors.java:81-134`)
   - Load HNSW index from disk
   - Read topics and extract query text/vectors
   - Initialize encoder if needed

2. **Batch Search** (`SearchHnswDenseVectors.java:144`)
   - Encode queries (if not pre-encoded)
   - Perform parallel HNSW search across threads
   - Collect top-k results per query

3. **Output** (`SearchHnswDenseVectors.java:146-160`)
   - Write results in TREC or MS MARCO format
   - Support for reranker request generation

### Flat Search Flow

Similar to HNSW but uses brute-force k-NN (`SearchFlatDenseVectors.java:49-205`). The API is intentionally identical for easy swapping.

## Common Issues

<AccordionGroup>
  <Accordion title="OutOfMemoryError with large indexes">
    Increase JVM heap: `-Xmx16g` for loading large vector indexes
    
    ```bash
    java -Xmx16g -cp anserini-1.6.0-fatjar.jar \
      io.anserini.search.SearchHnswDenseVectors ...
    ```
  </Accordion>
  
  <Accordion title="Slow HNSW search">
    Try:
    - Reduce `-efSearch` for faster (less accurate) search
    - Increase `-threads` for parallel execution
    - Use int8 quantized index for smaller memory footprint
  </Accordion>
  
  <Accordion title="Encoder not found">
    Ensure the encoder class name is exact (case-sensitive). Available encoders are in `io.anserini.encoder.dense.*` package.
  </Accordion>
</AccordionGroup>
