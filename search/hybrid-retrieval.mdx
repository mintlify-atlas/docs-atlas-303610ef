Hybrid retrieval combines the strengths of sparse (lexical) and dense (semantic) retrieval methods. By fusing results from both approaches, you can achieve better effectiveness than either method alone.

## Why Hybrid Retrieval?

Each retrieval paradigm has complementary strengths:

| Aspect | Sparse (BM25, SPLADE) | Dense (BGE, DPR) |
|--------|----------------------|------------------|
| **Matching** | Exact term overlap | Semantic similarity |
| **Strengths** | Rare terms, entities, precise matches | Paraphrases, synonyms, conceptual relevance |
| **Weaknesses** | Vocabulary mismatch | Poor on rare terms, entities |
| **Interpretability** | High (term-based) | Low (black-box embeddings) |

<Note>
Hybrid retrieval consistently outperforms either approach alone across diverse test collections, especially on queries requiring both lexical precision and semantic understanding.
</Note>

## Fusion Strategies

### Linear Score Fusion

The simplest approach combines normalized scores from each system:

```
score_hybrid = α × score_sparse + (1 - α) × score_dense
```

Where `α` controls the weight given to sparse vs dense retrieval.

### Rank Fusion

#### Reciprocal Rank Fusion (RRF)

RRF is parameter-free and effective:

```
RRF_score(d) = Σ [1 / (k + rank_i(d))]
```

For document `d` across systems `i`, with constant `k` (typically 60).

## Hybrid Search Workflow

<Steps>
  <Step title="Run Sparse Retrieval">
    Generate sparse retrieval results (e.g., BM25 or SPLADE)
    
    ```bash
    java -cp anserini-1.6.0-fatjar.jar io.anserini.search.SearchCollection \
      -index msmarco-v1-passage \
      -topics msmarco-v1-passage.dev \
      -output run.sparse.txt \
      -bm25 -hits 1000
    ```
  </Step>
  
  <Step title="Run Dense Retrieval">
    Generate dense retrieval results
    
    ```bash
    java -cp anserini-1.6.0-fatjar.jar io.anserini.search.SearchHnswDenseVectors \
      -index msmarco-v1-passage.bge-base-en-v1.5.hnsw \
      -topics msmarco-v1-passage.dev \
      -encoder BgeBaseEn15 \
      -output run.dense.txt \
      -hits 1000
    ```
  </Step>
  
  <Step title="Fuse Results">
    Use Pyserini or custom script to fuse run files
    
    ```python
    from pyserini.fusion import FusionMethod, FusionStrategy
    
    # Reciprocal Rank Fusion
    fused_run = FusionStrategy.fuse_runs(
        ['run.sparse.txt', 'run.dense.txt'],
        method=FusionMethod.RRF,
        k=60
    )
    ```
  </Step>
  
  <Step title="Evaluate">
    Evaluate the fused results
    
    ```bash
    java -cp anserini-1.6.0-fatjar.jar trec_eval -c -M 10 -m recip_rank \
      msmarco-v1-passage.dev run.hybrid.txt
    ```
  </Step>
</Steps>

## Choosing Fusion Weights

### Grid Search Approach

Test different α values on a development set:

```python
import numpy as np

best_mrr = 0
best_alpha = 0

for alpha in np.arange(0, 1.1, 0.1):
    # Fuse with current alpha
    fused_scores = alpha * sparse_scores + (1 - alpha) * dense_scores
    
    # Evaluate
    mrr = evaluate_mrr(fused_scores, qrels)
    
    if mrr > best_mrr:
        best_mrr = mrr
        best_alpha = alpha

print(f"Best α: {best_alpha}, MRR@10: {best_mrr}")
```

### Typical Weight Ranges

| Sparse Method | Dense Method | Suggested α |
|---------------|--------------|-------------|
| BM25 | BGE/DPR | 0.3-0.5 |
| SPLADE | BGE/DPR | 0.5-0.6 |

Optimal fusion weights vary by collection and query distribution. Always tune on a held-out development set.
</Note>

## Multi-Stage Hybrid Pipeline

For production systems, use a cascaded approach:

<Steps>
  <Step title="Stage 1: Sparse Retrieval">
    Fast first-stage retrieval with BM25 or SPLADE
    
    - Retrieve top-1000 candidates
    - Handles exact matching, entities
    - Very efficient (~1-10ms per query)
  </Step>
  
  <Step title="Stage 2: Dense Re-ranking">
    Re-rank sparse results with dense vectors
    
    - Score top-100 sparse results with dense encoder
    - Adds semantic relevance signal
    - Still fast (~10-50ms)
  </Step>
  
  <Step title="Stage 3: Fusion">
    Combine sparse and dense scores
    
    - Linear fusion or RRF on top-100
    - Produces final ranking
  </Step>
  
  <Step title="Stage 4: Neural Re-ranking (Optional)">
    Apply cross-encoder for top-k results
    
    - Use models like monoT5, BERT re-ranker
    - Highest quality but slowest
    - Only on top-10 to top-20
  </Step>
</Steps>

## Implementation Example

Here's a complete hybrid retrieval script:

```python
import subprocess
import json
from collections import defaultdict

def run_sparse_retrieval(index, topics, output):
    """Run BM25 sparse retrieval"""
    cmd = [
        'java', '-cp', 'anserini-1.6.0-fatjar.jar',
        'io.anserini.search.SearchCollection',
        '-index', index,
        '-topics', topics,
        '-output', output,
        '-bm25', '-hits', '1000'
    ]
    subprocess.run(cmd, check=True)

def run_dense_retrieval(index, topics, encoder, output):
    """Run dense vector retrieval"""
    cmd = [
        'java', '-cp', 'anserini-1.6.0-fatjar.jar',
        'io.anserini.search.SearchHnswDenseVectors',
        '-index', index,
        '-topics', topics,
        '-encoder', encoder,
        '-output', output,
        '-hits', '1000'
    ]
    subprocess.run(cmd, check=True)

def load_run(filepath):
    """Load TREC run file"""
    run = defaultdict(dict)
    with open(filepath) as f:
        for line in f:
            qid, _, docid, rank, score, _ = line.strip().split()
            run[qid][docid] = float(score)
    return run

def reciprocal_rank_fusion(runs, k=60):
    """Perform RRF on multiple runs"""
    fused = defaultdict(dict)
    
    for qid in runs[0].keys():
        scores = defaultdict(float)
        
        for run in runs:
            # Sort by score and assign ranks
            sorted_docs = sorted(run[qid].items(), 
                               key=lambda x: x[1], reverse=True)
            for rank, (docid, _) in enumerate(sorted_docs, 1):
                scores[docid] += 1.0 / (k + rank)
        
        fused[qid] = scores
    
    return fused

def write_run(run, output_path, runtag='hybrid'):
    """Write fused results as TREC run"""
    with open(output_path, 'w') as f:
        for qid, doc_scores in run.items():
            sorted_docs = sorted(doc_scores.items(), 
                               key=lambda x: x[1], reverse=True)
            for rank, (docid, score) in enumerate(sorted_docs[:1000], 1):
                f.write(f"{qid} Q0 {docid} {rank} {score} {runtag}\n")

# Main hybrid pipeline
if __name__ == '__main__':
    # Step 1: Sparse retrieval
    run_sparse_retrieval(
        'msmarco-v1-passage',
        'msmarco-v1-passage.dev',
        'run.sparse.txt'
    )
    
    # Step 2: Dense retrieval
    run_dense_retrieval(
        'msmarco-v1-passage.bge-base-en-v1.5.hnsw',
        'msmarco-v1-passage.dev',
        'BgeBaseEn15',
        'run.dense.txt'
    )
    
    # Step 3: Load runs
    sparse_run = load_run('run.sparse.txt')
    dense_run = load_run('run.dense.txt')
    
    # Step 4: Fuse with RRF
    fused_run = reciprocal_rank_fusion([sparse_run, dense_run], k=60)
    
    # Step 5: Write output
    write_run(fused_run, 'run.hybrid.txt', runtag='BM25+BGE-RRF')
    
    print("Hybrid retrieval complete! Evaluate with:")
    print("  trec_eval -c -M 10 -m recip_rank msmarco-v1-passage.dev run.hybrid.txt")
```

## When to Use Hybrid

<CardGroup cols={2}>
  <Card title="Use Hybrid When" icon="check">
    - Queries mix entities and concepts
    - Need robust cross-domain retrieval
    - Production system (belt-and-suspenders)
    - Optimizing for top-10 precision
  </Card>
  
  <Card title="Sparse Alone May Suffice" icon="database">
    - Entity-heavy queries (e.g., biomedical)
    - Very large collections (>100M docs)
    - Resource constraints (latency/cost)
    - Learned sparse (SPLADE) already strong
  </Card>
</CardGroup>

## Advanced: Learning Fusion Weights

For best results, train fusion weights on labeled data:

```python
from sklearn.linear_model import LogisticRegression
import numpy as np

# Collect features: [sparse_score, dense_score]
X_train = np.array([
    [sparse_scores[q][d], dense_scores[q][d]] 
    for q in queries for d in candidates
])

# Binary labels: relevant or not
y_train = np.array([qrels[q].get(d, 0) for q, d in doc_pairs])

# Train logistic regression
model = LogisticRegression()
model.fit(X_train, y_train)

# Learned weights
print(f"Sparse weight: {model.coef_[0][0]}")
print(f"Dense weight: {model.coef_[0][1]}")
```

This approach optimizes fusion weights directly for the target metric.
