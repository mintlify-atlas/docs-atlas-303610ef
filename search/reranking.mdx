Reranking refines initial retrieval results by applying more sophisticated (and expensive) scoring methods. Anserini supports pseudo-relevance feedback (PRF) rerankers that expand queries using top-retrieved documents.

## Why Rerank?

Reranking improves retrieval through:

1. **Query expansion** - Add terms from relevant documents to capture more aspects
2. **Vocabulary enrichment** - Bridge the vocabulary gap between queries and documents  
3. **Context incorporation** - Use collection statistics from pseudo-relevant docs

<Note>
Reranking typically improves Mean Average Precision (MAP) by 10-30% on standard test collections, with larger gains on difficult queries.
</Note>

## Relevance Model 3 (RM3)

RM3 is the most widely used PRF method. It estimates a relevance model from top-retrieved documents and interpolates it with the original query.

### Basic Usage

```bash
java -cp anserini-1.6.0-fatjar.jar io.anserini.search.SearchCollection \
  -index msmarco-v1-passage \
  -topics msmarco-v1-passage.dev \
  -output run.msmarco.bm25+rm3.txt \
  -bm25 -rm3
```

### RM3 Algorithm

From `Rm3Reranker.java:79-100`, RM3 works as follows:

<Steps>
  <Step title="Initial Retrieval">
    Retrieve top-k documents with BM25 or other base ranker
  </Step>
  
  <Step title="Relevance Model Estimation">
    Build term distribution from feedback documents:
    ```
    P(w | R) ∝ Σ P(w | d) × P(d | q)
    ```
    Where d ranges over feedback documents
  </Step>
  
  <Step title="Query Interpolation">
    Combine original and expanded query:
    ```
    q_new = λ × q_original + (1 - λ) × RM
    ```
    Default λ = 0.5 (originalQueryWeight)
  </Step>
  
  <Step title="Re-ranking">
    Score documents with expanded query and return top results
  </Step>
</Steps>

## Rocchio Algorithm

Rocchio is a vector-space reranking method that adjusts the query vector toward relevant documents and away from non-relevant ones.

### Usage

```bash

  -topics msmarco-v1-passage.dev \
  -output run.msmarco.bm25+rocchio.txt \
  -bm25 -rocchio
```

| Parameter | Description | Default |
|-----------|-------------|--------|
| `-rocchio.topFbTerms` | Expansion terms from relevant docs | 10 |
| `-rocchio.topFbDocs` | Number of relevant feedback docs | 10 |
| `-rocchio.bottomFbTerms` | Terms from non-relevant docs | 10 |
| `-rocchio.bottomFbDocs` | Number of non-relevant docs | 10 |
| `-rocchio.alpha` | Weight for original query | 1.0 |
| `-rocchio.beta` | Weight for relevant docs | 0.75 |
| `-rocchio.gamma` | Weight for non-relevant docs | 0.15 |
| `-rocchio.useNegative` | Use negative feedback | false |

### Rocchio Formula

From `RocchioReranker.java:92-96`, the classic Rocchio formula:

```
q_new = α × q + β × (1/|R|) × Σ d_r - γ × (1/|N|) × Σ d_n
```

Where:
- `q` = original query vector
- `d_r` = relevant document vectors
- `d_n` = non-relevant document vectors
- `|R|`, `|N|` = number of relevant/non-relevant docs

<Note>
Rocchio uses L2-normalized vectors (`RocchioReranker.java:96`), while RM3 uses L1 normalization. This affects how term weights are distributed.
</Note>

### BM25PRF Mechanism

From `BM25PrfReranker.java:55-100`, BM25PRF:

1. Uses a modified BM25Similarity without IDF (`BM25PrfSimilarity.java:63-65`)
2. Scores terms in feedback documents using this modified BM25
3. Selects top-k expansion terms by score
4. Combines original and expansion terms with configurable weights

<Note>
BM25PRF defaults to 20 expansion terms (vs 10 for RM3), reflecting that BM25 scoring provides more discriminative term selection.
</Note>

## Comparing Rerankers

### Performance Characteristics

| Reranker | Speed | Effectiveness | Best For |
|----------|-------|--------------|----------|
| **RM3** | Fast | +10-20% MAP | General purpose, standard benchmark |
| **Rocchio** | Fast | +10-15% MAP | When negative feedback available |
| **BM25PRF** | Fast | +15-25% MAP | Term-centric queries |
| **Axiomatic** | Moderate | Varies | Semantic matching, experimental |

## Implementation Details

### Reranker Architecture

From `RerankerCascade.java` and `Reranker.java`, Anserini's reranking uses a pipeline pattern:

```java
// Simplified architecture
public interface Reranker<T> {
  ScoredDocs rerank(ScoredDocs docs, RerankerContext<T> context);
}

public class RerankerCascade<T> {
  List<Reranker<T>> rerankers;
  
  public ScoredDocs run(ScoredDocs docs, RerankerContext<T> context) {
    for (Reranker<T> reranker : rerankers) {
      docs = reranker.rerank(docs, context);
    }
    return docs;
  }
}
```

This allows chaining multiple rerankers sequentially.

### Adding Custom Rerankers

Implement the `Reranker` interface:

```java
public class MyReranker<T> implements Reranker<T> {
  @Override
  public ScoredDocs rerank(ScoredDocs docs, RerankerContext<T> context) {
    // Custom reranking logic
    IndexSearcher searcher = context.getIndexSearcher();
    Query query = context.getQuery();
    
    // Re-score documents
    for (int i = 0; i < docs.ids.length; i++) {
      docs.scores[i] = customScore(docs.ids[i], query, searcher);
    }
    
    // Re-sort by new scores
    return docs.sort();
  }
}
```

## Best Practices

<AccordionGroup>
  <Accordion title="When to use PRF reranking">
    - Long queries benefit less (already rich)
    - Short keyword queries benefit most
    - Homogeneous collections work better
    - Initial retrieval must be reasonable (>50% recall@1000)
  </Accordion>
  
  <Accordion title="Tuning parameters">
    - Start with defaults (well-tuned on standard collections)
    - Increase fbDocs for noisy collections
    - Increase fbTerms for diverse/multi-aspect queries
    - Increase originalQueryWeight if expansion hurts (query drift)
  </Accordion>
  
  <Accordion title="Combining multiple rerankers">
    - Don't chain multiple PRF methods (redundant)
    - DO: BM25 → RM3 → Neural Reranker ✓
    - DON'T: BM25 → RM3 → Rocchio → BM25PRF ✗
  </Accordion>
</AccordionGroup>

## Performance Tips

1. **Limit initial retrieval depth**: Use `-rerankCutoff` to only rerank top-k:
   ```bash
   -bm25 -rm3 -rerankCutoff 100
   ```
   This reranks only top-100, not all 1000 retrieved docs.

2. **Parallelize**: Enable multi-threading for large query sets:
   ```bash
   -bm25 -rm3 -threads 16
   ```

3. **Output expanded queries**: Debug with `-rm3.outputQuery` to see expansion terms:
   ```bash
   -bm25 -rm3 -rm3.outputQuery
   ```

## Common Issues

<Warning>
**Query drift**: If reranking hurts, your feedback documents may be off-topic. Try:
- Increasing `-rm3.originalQueryWeight` (e.g., 0.7 or 0.8)
- Reducing `-rm3.fbDocs` to use fewer feedback documents
- Switching to a different base ranker
</Warning>

<Note>
**No improvement on neural retrieval**: PRF reranking was designed for lexical retrieval (BM25). It may not help dense retrieval much, since dense models already perform implicit expansion.
</Note>
