Sparse retrieval uses term-based representations where documents and queries are represented by sparse vectors. Anserini supports both traditional bag-of-words models and modern learned sparse representations.

## Traditional Sparse Retrieval

### BM25 (Best Match 25)

BM25 is the most widely used sparse retrieval model. Anserini uses default parameters of `k1=0.9` and `b=0.4` based on research by Trotman et al. (SIGIR 2012).

<CodeGroup>
```bash Basic BM25
java -cp anserini-1.6.0-fatjar.jar io.anserini.search.SearchCollection \
  -index msmarco-v1-passage \
  -topics msmarco-v1-passage.dev \
  -output run.msmarco.bm25.txt \
  -bm25
```

```bash Custom Parameters
java -cp anserini-1.6.0-fatjar.jar io.anserini.search.SearchCollection \
  -index msmarco-v1-passage \
  -topics msmarco-v1-passage.dev \
  -output run.msmarco.bm25-custom.txt \
  -bm25 -bm25.k1 1.2 -bm25.b 0.75
```

```bash Accurate BM25
java -cp anserini-1.6.0-fatjar.jar io.anserini.search.SearchCollection \
  -index msmarco-v1-passage \
  -topics msmarco-v1-passage.dev \
  -output run.msmarco.bm25-accurate.txt \
  -bm25.accurate
```
</CodeGroup>

<Note>
The `-bm25.accurate` option uses accurate document lengths at the cost of slower retrieval. Regular BM25 uses approximate document lengths for better performance.
</Note>

**Expected Results (MS MARCO Passage Dev):**
- BM25 (k1=0.9, b=0.4): **MRR@10 = 0.1840**

### Query Likelihood Models

Anserini supports language modeling approaches with Dirichlet and Jelinek-Mercer smoothing.

<Tabs>
  <Tab title="Dirichlet Smoothing">
```bash
java -cp anserini-1.6.0-fatjar.jar io.anserini.search.SearchCollection \
  -index msmarco-v1-passage \
  -topics msmarco-v1-passage.dev \
  -output run.msmarco.qld.txt \
  -qld -qld.mu 1000
```

Dirichlet smoothing uses a parameter `mu` (default: 1000) that controls the amount of smoothing. Larger values provide more smoothing and are safer for long queries.
  </Tab>
  
  <Tab title="Jelinek-Mercer Smoothing">
```bash
java -cp anserini-1.6.0-fatjar.jar io.anserini.search.SearchCollection \
  -index msmarco-v1-passage \
  -topics msmarco-v1-passage.dev \
  -output run.msmarco.qljm.txt \
  -qljm -qljm.lambda 0.1
```

Jelinek-Mercer smoothing uses lambda (default: 0.1) to interpolate between document and collection language models.
  </Tab>
</Tabs>

## Learned Sparse Retrieval

Learned sparse representations use neural models to generate weighted term vectors. Unlike dense embeddings, these representations remain interpretable and can leverage inverted indexes.

### SPLADE-v3

SPLADE (Sparse Lexical AnD Expansion) learns to expand queries and documents with related terms while maintaining sparsity.

```bash
java -cp anserini-1.6.0-fatjar.jar io.anserini.search.SearchCollection \
  -index msmarco-v1-passage.splade-v3 \
  -topics msmarco-v1-passage.dev \
  -encoder SpladeV3 \
  -output run.msmarco.splade-v3.txt \
  -impact -pretokenized
```

**Expected Results:**
- SPLADE-v3: **MRR@10 = 0.4000**

<Note>
The `-impact` flag tells Anserini to use impact scores (weighted term frequencies) rather than traditional BM25 scoring. The `-pretokenized` flag indicates the index already contains encoded representations.
</Note>

## Sequential Dependence Model (SDM)

SDM extends bag-of-words retrieval by considering term proximity through ordered and unordered windows.

```bash
java -cp anserini-1.6.0-fatjar.jar io.anserini.search.SearchCollection \
  -index msmarco-v1-passage \
  -topics msmarco-v1-passage.dev \
  -output run.msmarco.sdm.txt \
  -bm25 -sdm
```

Customize weights with:
- `-sdm.tw` (term weight, default: 0.85)
- `-sdm.ow` (ordered window weight, default: 0.1) 
- `-sdm.uw` (unordered window weight, default: 0.05)

## Performance Comparison

| Method | Type | MRR@10 (MS MARCO) |
|--------|------|------------------|
| BM25 | Traditional | 0.1840 |
| uniCOIL (noexp) | Learned Sparse | 0.3508 |
| uniCOIL + doc2query | Learned Sparse | 0.3520 |
| SPLADE++ ED | Learned Sparse | 0.3830 |
| SPLADE-v3 | Learned Sparse | **0.4000** |

<Note>
Learned sparse methods significantly outperform traditional BM25 while maintaining the efficiency of inverted indexes and interpretability of term-based retrieval.
</Note>
